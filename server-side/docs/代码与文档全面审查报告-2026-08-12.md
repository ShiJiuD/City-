## 一、高严重度(7 项,部署前必须修复)

### 1. 重置密码接口零验证码校验 → 任意账号接管(含管理员)🔴
- **位置**:`CommonController.java:64-91`(配合 37、48-62 行)
- **问题**:`resetPassword` 只查手机号存在就改密,完全不校验验证码;`ResetPasswordDTO` 无 `code` 字段;`verify-code` 只和硬编码 `MOCK_VERIFY_CODE = "666666"` 比对且**无服务端状态**;`/api/reset-password` 在拦截器排除名单(免登录)。知道手机号即可重置任意 user/admin 密码。
- **修复**:验证码校验通过后写入 Redis(`verify:code:{phone}`,TTL 5 分钟——常量已有),reset 必须携带 code 校验通过才改密;上线前移除 mock 码。

### 2. 管理员表名三方不一致 → 管理员登录必挂 🔴
- **位置**:`AdminUser.java:25` `@TableName("admin_user")` vs 实际库/seed/建表文档均为 `admin`(实测 `SELECT * FROM admin_user` 报 1146 表不存在)
- **修复**:实体改 `@TableName("admin")`(与库一致);《01登录接口文档》附录二残留 `admin_user` 一并统一。

### 3. SQL 脚本源文件从仓库丢失 🔴
- **位置**:`cityart-server/src/main/resources/sql/` 目录已不存在,只剩 `target/classes/sql/` 构建副本,**从未进入 git 历史**
- **修复**:立即把 `exhibition_work.sql`、`schema_update_favorite_and_work.sql`、`seed_test_data.sql` 还原到 `src/main/resources/sql/` 并提交。

### 4. 订单状态机死端:取消功能实际不可达 🔴
- **位置**:`OrderServiceImpl.java:293、329` + `OrderStreamConsumer.java` 落库 `status=1`;`cancelOrder` 要求 `status=0`(全链路无任何路径产生 0)
- **后果**:取消永远抛"当前状态不可取消";"待支付"Tab 恒空
- **修复**:要么下单落 `status=0` 并补"支付"接口,要么按"下单即支付"重设取消/退款状态机(与《03订单接口文档》附录四"下单即已支付"对齐)。

### 5. XADD 失败时已扣库存不回滚 → 库存泄漏、用户付钱无单 🔴
- **位置**:`OrderServiceImpl.java:216-264`(try 块)vs `288`(XADD 在 try 外)
- **修复**:XADD 纳入 try,失败时 `rollbackStock(decrKeys)` 后重抛;或重试一次再回滚。

### 6. pending-list 毒消息无限重试 → 整条订单消费管线停摆 🔴
- **位置**:`OrderStreamConsumer.java:223-269`(handlePendingList 单线程无限循环;消费者是单线程 88 行)
- **场景**:某条消息永久失败(`NumberFormatException`/`updateSoldCount=0` 抛 RuntimeException),永远 break 不出来,后续所有订单不再落库
- **修复**:重试次数上限(如 5 次),超限 XACK + ERROR 告警(或写入死信 Stream)。

### 7. 抢锁失败消息被无条件 XACK → 订单静默丢失 🔴
- **位置**:`OrderStreamConsumer.java:310-329`(processOrder 抢锁失败 return)+ `188-192`(无条件 acknowledge)
- **修复**:抢锁失败抛异常(进 pending 重试)或 `tryLock(waitTime)` 阻塞等待。

## 四、做得好的(审查确认为安全/正确)

- **SQL 注入**:全部 mapper XML 用 `#{}` 参数化,无一处 `${}`;LambdaQueryWrapper 参数化
- **密码**:BCrypt(10 轮),登录统一"账号或密码错误"文案
- **越权**:订单详情/取消/退款均有归属校验;订单列表按 userId 过滤
- **缓存体系**:Cache Aside + 互斥锁双检 + 空值缓存防穿透 + TTL 随机抖动防雪崩 + 判等释放;序列化异常优雅降级;key 前缀不冲突
- **消费端**:幂等判断(return 不抛异常)、锁覆盖事务提交(拆两层 + self 代理)、消费者组 MKSTREAM 自愈、running 标志优雅停止
- **性能**:无 N+1(订单批量 IN、收藏联表、详情定点查询);分页自动 count
- **数据库**:8 张表与建表文档逐字段吻合(仅 admin 表名、banner.title 默认值两处偏差);seed 数据内部自洽
- **文档同步度**:02/03/04/05/06 五份接口文档与代码几乎完全对齐
